# 单机方案评审：总工是方向会话，不是审批人

> 评审对象：`.sap.local` 文件状态 + 一个总工后台会话 + `dsh-qingshen` 注入 + worker 写文件等总工意见的单机结构。  
> 评审时间：2026-11-17。本文只做设计与风险评审，不实现插件、后台服务或 CLI。

## 1. 结论

**方向可行，而且适合单机；但上一版把它写成了“云端审批流的精简版”，这是错的。**

单机版没有审批问题：没有 G1/G2/G3、没有 approve/reject、没有 lease/grant/contract。单机只有一个人、多个会话，真正要解决的是：

1. **总工被操作细节污染**：总工只该看方向，不该看 bug 日志/diff/复现。
2. **简报路由不可靠**：靠 watcher/append 文件会半写、重复、丢事件。
3. **提示词不是边界**：qingshen 注入只能提醒，不能阻止会话把日志贴进总工上下文。

**一句话：单机版的核心功能是“方向会话与工作会话的隔离”，不是“谁批谁”。**

云端与单机的职责划分见 [云端与单机职责边界](06_云端与单机职责边界.md)。

## 2. 哪些要保留

- **`.sap.local` 本地状态**：透明、可 diff、可备份、可离线。
- **一个总工席位**：让方向/结构/优先级有一个稳定入口。
- **worker 先判断再升级**：不是所有事都找总工。
- **worker 可以不同意**：单机就是自己跟 AI 讨论，允许提出异议。
- **qingshen 注入**：给每个会话一个默认行为提示；但不把它当强制门禁。
- **`.sap.local` / `.sap.cloud` 分离**：同一套“方向/操作分离”原则，不同治理强度。

## 3. P0：总工上下文污染

### 问题

如果总工看到的是每个会话的日志、diff、复现、调试对话，那么：

- 总工上下文被“这次调了什么 bug”占满，目标、原则、取舍被挤到边缘。
- 总工越来越像高级 Debugger，而不是方向负责人。
- 上下文压缩后，留下零散 bug 记忆，丢掉“为什么做、不做什么、什么不能变”。
- 多个 worker 把细节推给总工，总工成为污染汇聚点。

**单机版最重要的功能，就是不让这件事发生。**

### 建议

把信息分成两层，中间只走**一页简报**：

| 层 | 谁看 | 内容 | 进总工上下文？ |
|---|---|---|---|
| 方向层 | 总工 | `direction.md`：目标、原则、结构、优先级、风险、待定问题 | 是 |
| 简报层 | 总工 | `briefs/brief-*.md`：问题、影响、选项、建议、需要什么方向判断 | 是（只此一层） |
| 操作层 | worker | `work/<session>/`：代码、diff、日志、复现、调试过程 | **否** |
| 细节包 | 总工按需 | 由人手动提供，限定范围/时限 | 仅当次，不合并 |

硬规则：

- 总工只挂载 `direction.md` + `briefs/` + `notes/`；**不读 `work/`**。
- 简报一页；**不含** stack trace、逐行 diff、调试对话、原始日志。
- 需要细节时，由人手动摘录到 `detail-*.md`，注明目的和时限；看完只写结论，不把原文回填。
- 不自动把 worker 日志转发给总工；不订阅每个 bug 的讨论。
- 每个阶段重置方向包；归档过期简报/细节。

## 4. P1：简报路由不是可靠队列

单机也会出问题：

- **半写**：worker 正写 brief，watcher 读到一半。
- **重复**：编辑器保存、watcher 重启，重复触发。
- **丢失**：watcher 启动前已存在的 brief、睡眠期间的事件。
- **覆盖**：两个会话同时写同一个 `pending.md`。
- **Windows 文件锁**：读写/rename 失败。

建议：

- 一个 brief 一个文件：`briefs/brief-<ULID>.md`，用“临时文件 + rename”写入，写完即不可变。
- watcher 只触发扫描，**目录扫描是事实来源**；启动先全量扫描。
- 重复 ID 幂等；同 ID 不同内容报冲突，不覆盖。
- 需要改 brief：写新版本 `brief-<id>-v2.md`，不覆盖旧文件。
- 不把多个会话的 brief append 到同一个文件。

## 5. P1：提示词不是边界

本机已安装 `dsh-qingshen` 2.2.0。它的实现是：在 `agent/pre-step` 里按会话选择的模式，把一段文本追加到最后一条人类消息；文本会进入会话日志，模型收到的就是注入后的内容。模式在 `modes.json` 里配置，默认“张飞”，可加“诸葛亮”等空模式。

这解释了为什么提示词只能提醒、不能当边界：

- 模型可能忽略、误判，或被仓库内容诱导。
- 注入发生在消息发送时，但会话中途改规则，模型可能还用旧规则。
- 不能阻止会话主动 `cat work/...` 或把日志贴进总工上下文。
- qingshen 的注入会进入历史；如果文本里带操作细节，反而加重污染。

所以：

- **隔离靠目录/会话/权限，不靠提示词。** 总工会话不挂载 `work/`；至少不把 `work/` 放进它的默认上下文。
- 提示词只负责“提醒先判断、先写简报、别贴日志”。
- qingshen 适合做“每轮提醒”；本插件选择 `systemPrompt.section`（不进入历史）作为默认角色协议，二者可二选一或叠加，但不要重复注入。
- 本机 qingshen 的能力已核验到“按模式追加文本”这一层；它不提供锁、权限或会话隔离。

## 6. 单机最小模型（没有审批）

| 对象 | 作用 |
|---|---|
| Direction | `direction.md`：当前目标、原则、结构、优先级、风险、待定问题 |
| Brief | 工作会话给总工的一页问题/选项/建议；不是审批申请 |
| DirectionNote | 总工给的方向判断/原则/建议；不是 approve/reject |
| Session | 会话 id、角色（none/chief/worker）、当前焦点、最近 brief |
| WorkLog | 工作会话的操作记录，留在 `work/<session>/`，总工不读 |

流程：

```text
worker 收到任务
  -> 先看 direction.md
  -> 判断：这是方向问题，还是实现细节？
      实现细节：自己做，写 work/<session>/log.md，不打扰总工
      方向问题：写 briefs/brief-<id>.md（一页），继续做不冲突的部分
  -> 总工读 direction + briefs，写 notes/note-<id>.md
  -> worker 下次读 note，采纳/调整/提出异议
  -> 如果方向变了，总工更新 direction.md
```

**没有“等待批准”**。worker 可以继续不冲突的工作；只有方向依赖的部分暂停。总工 note 是指导，不是授权；最终由你决定。

## 7. 典型失效场景

| 场景 | 天真实现 | 需要的行为 |
|---|---|---|
| worker 把 stack trace 贴进 brief | 总工开始分析 bug | 总工退回：“这是操作细节，给我一页方向问题” |
| 连续 20 条 bug 日志推给总工 | 总工逐条看，方向被淹没 | 总工拒绝，要求汇总为“是否影响方向/结构” |
| 总工会话和 worker 共用 | bug 上下文直接进总工 | 独立 session/工作区；`work/` 不进总工上下文 |
| brief 写一半 watcher 读到 | JSON/MD 解析失败 | 临时文件 + rename；只处理完整文件 |
| watcher 重启 | 睡眠期间的 brief 丢了 | 启动全量扫描；目录是事实来源 |
| 两个会话写同一 brief | 覆盖/乱序 | 一 brief 一文件；新版本不覆盖 |
| 总工 note 被当成批准 | worker 以为可以上线 | 单机没有审批；note 只是方向指导，上线由你决定 |
| `.sap.local` 被 git 提交 | 隐私/密钥泄露 | 默认 gitignore；只导出脱敏方向记录 |
| 会话 fork/compact | session id 变了，找不到 brief | 用 brief id 关联；brief 不绑定进程 |

## 8. 需要你确认的 4 个问题

1. **总工是谁**：是你自己的一个方向会话，还是 AI 自动读 brief 写 note？建议“你 + AI 助理”，AI 只给方向建议。
2. **什么算方向问题**：目标、原则、结构、优先级、跨会话冲突、你拿不准的事；实现细节不升级。要不要一份显式清单？
3. **简报格式**：一页够不够？要不要固定字段（问题/影响/选项/建议/需要什么判断）？
4. **细节怎么给**：只由你手动摘录，还是允许总工申请一次 `detail`？后者需要限定范围/时限。

## 9. 与云端版的关系

- 云端：多人、多角色、审批、证据、责任链；G1/G2/G3 是正式治理。
- 单机：一个人、多会话、方向连续性、防污染；**没有审批**。
- 共同点只有一条：方向层不读操作层；一页简报；细节按需、限时。
- 不要把云端的 Contract/Lease/Evidence/Acceptance 搬进 `.sap.local`。

详见 [云端与单机职责边界](06_云端与单机职责边界.md)。
