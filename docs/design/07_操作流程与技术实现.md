# 单机 SAP 操作流程与技术实现方案

> 版本：v1 草案  
> 适用范围：`dsh-sap-local` 单机版  
> 关系：01–05 讲“为什么”和“边界”，06 讲云端/单机分工；本文只讲**怎么跑起来、每个功能点怎么实现**。  
> 结论先说：单机 SAP 不是审批系统，也不是表单后台。它是**方向连续性层**：用独立会话和 `.sap.local` 让“方向”不被“操作细节”淹没。

---

## 1. 先纠偏：功能和定位

### 1.1 正确的定位

单机 SAP 解决三个问题：

1. **方向会话被污染**：日志、diff、复现、调试对话进入总工上下文，总工看不到目标和取舍。
2. **工作会话缺少方向约束**：worker 边做边改方向，或者所有小事都去问总工。
3. **会话/进程会断**：总工会话关掉、电脑重启后，方向工作没有可恢复的入口。

它不解决：

- 多人审批、责任链、G1/G2/G3；
- 代码执行、CI、部署；
- 自动判断方向对错；
- 替代 Git 或项目管理工具。

### 1.2 当前实现的偏差

| 偏差 | 表现 | 纠正 |
|---|---|---|
| 把操作条做成按钮堆 + 表单后台 | 10 个按钮、每个都开面板 | 操作条是**控制面**：状态 + 上下文主操作 + 更多菜单 |
| 把初始化做成表单 | 逐题 textarea | 初始化是**多轮对话**：总工 agent 追问，工具记录 |
| 总工在线靠进程判断 | `host_pid + ctx.agents` | 改成**租约**：claim / renew / release / expire |
| 命令、路由、客户端三套逻辑 | 同一操作多处实现 | 收敛到唯一 `SapService` |
| 状态源分散 | `state.json`、`chief.json`、内存 map | `project.json` + `chief.json` 为事实源，其他派生 |

### 1.3 两个面，不要混

```text
对话面：用户 ↔ 总工/工作 agent
        负责“方向共识、brief/note 的内容”

控制面：SAP 操作条
        负责“角色、状态、开始/继续/接管、短表单”
```

操作条不能替代对话；对话也不应该要求用户记命令。

## 2. 角色、对象、边界

### 2.1 角色

| 角色 | 谁 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 用户 | 人 | 决定方向、选择角色、接管总工、最终拍板 | — |
| 总工 chief | 一个方向会话 | 初始化、读 direction/briefs/notes、写 note、排污、接管 | 不读 `work/`、不写代码、不做审批 |
| 工作 worker | 任意工作会话 | 实现/调试、写 `work/`、写 brief、读 note | 不改 direction、不替总工做方向判断 |
| 无角色 none | 任意会话 | 零散任务，不参与 SAP | 不使用 SAP 协议、不写 SAP 状态 |
| 插件 host | DSH 进程 | 状态机、租约、文件事务、路由、工具 | 不替人做方向决定 |
| 操作条 | 浏览器 | 展示状态、触发操作、显示回执 | 不静默改状态 |

### 2.2 对象

| 对象 | 文件 | 说明 |
|---|---|---|
| Project | `.sap.local/project.json` | 阶段、schema、方向版本 |
| Chief lease | `.sap.local/chief.json` | 当前总工、租约、epoch |
| Session | `.sap.local/sessions/<sid>.json` | 角色、加入时间、最近活动 |
| Direction | `.sap.local/direction.md` | 人读的方向 |
| Brief | `.sap.local/briefs/<id>.md` | worker 给总工的一页方向问题 |
| Note | `.sap.local/notes/<id>.md` | 总工的方向判断/建议 |
| WorkLog | `.sap.local/work/<sid>/log.md` | 操作层，总工不读 |
| Event | `.sap.local/events.jsonl` | 状态变更审计 |
| Archive | `.sap.local/archive/` | reinit/导入/排污归档 |

### 2.3 硬边界

- 没有 approve/reject、G1/G2/G3、lease grant/contract。
- 总工不读 `work/`；brief 不含日志/diff/stack trace。
- 一个工作区同一时刻最多一个**有效**总工。
- `.sap.local` 默认 gitignore；导出不带 `work/`。
- 任何操作必须有可见回执；不能“点了没反应”。

## 3. 数据模型

### 3.1 目录

```text
.sap.local/
├── project.json
├── chief.json
├── direction.md
├── charter.md
├── README.md
├── sessions/
│   └── <session-id>.json
├── briefs/
│   └── brief-<id>.md
├── notes/
│   └── note-<id>.md
├── work/
│   └── <session-id>/log.md
├── templates/
│   ├── brief.md
│   └── note.md
├── events.jsonl
├── archive/
│   ├── reinit-<stamp>/
│   └── import-<stamp>/
├── exports/
└── backups/
```

### 3.2 `project.json`

```json
{
  "schema": "sap.local/project/v1",
  "project_id": "uuid",
  "phase": "uninitialized",
  "direction_version": 0,
  "created_at": "2026-11-17T10:00:00Z",
  "updated_at": "2026-11-17T10:00:00Z",
  "legacy": false
}
```

`phase`：

- `uninitialized`：没有有效 direction；
- `interviewing`：初始化对话进行中；
- `reinitializing`：旧项目重新共识中；
- `active`：direction 有效，可日常工作。

### 3.3 `chief.json`（租约）

```json
{
  "schema": "sap.local/chief/v1",
  "session_id": "session-...",
  "lease_id": "uuid",
  "epoch": 3,
  "lease_until": "2026-11-17T10:00:30Z",
  "host_id": "host-uuid",
  "released_at": null
}
```

判定：

- `lease_until > now` 且 `released_at == null` → 有效总工；
- 过期或 release → 无人持有；
- 其他会话只能 claim，不能直接改 `session_id`。

`epoch` 每次 claim +1，用于拒绝旧租约的续租/写操作。

### 3.4 `sessions/<sid>.json`

```json
{
  "schema": "sap.local/session/v1",
  "session_id": "session-...",
  "role": "none",
  "joined_at": "...",
  "last_seen_at": "...",
  "note": ""
}
```

角色只存 `none/worker`。  
`chief` 不靠这个文件，靠 `chief.json` 租约；UI 上“总工”= `chief.session_id === session_id && lease 有效`。  
旧总工租约失效后，session 文件角色降为 `none`，避免“两个 chief 文件”。

### 3.5 Direction

`direction.md` 由初始化生成，只写长期有效内容：

```markdown
# Direction

> 由 SAP 初始化生成；版本 1；最后更新：...

## 目标
...
## 当前重点
...
## 非目标
...
## 结构与约束
...
## 取舍原则
...
## 暂停/复核触发
...
```

### 3.6 Brief

```markdown
---
id: brief-...
status: open
session: session-...
created_at: ...
updated_at: ...
---

# Brief: <一句话问题>

- 方向关联：
- 问题：
- 影响：
- 选项：
- 建议：
- 需要总工判断：
- 证据指针：
- 已知未知：
```

`status: open | resolved`。  
brief 是“咨询”，不是“申请”，不要求 worker 停下等待。

### 3.7 Note

```markdown
---
id: note-...
brief: brief-...
session: session-...
created_at: ...
---

# Note: <对应 brief>

> 这是方向指导，不是审批；最终由用户决定。

- 结论：
- 理由：
- 适用范围：
- 复核触发：
```

### 3.8 `events.jsonl`

一行一个事件，append-only：

```json
{"at":"...","type":"project.init.start","session":"...","data":{}}
{"at":"...","type":"init.answer","session":"...","data":{"qid":"q1"}}
{"at":"...","type":"chief.claim","session":"...","data":{"epoch":4}}
{"at":"...","type":"brief.create","session":"...","data":{"id":"brief-..."}}
```

用途：

- `doctor` 检查；
- 崩溃后解释状态；
- 导出时可选；
- 不做 UI 主状态源（UI 读 snapshot）。

### 3.9 原子写与锁

- 所有 JSON/Markdown 写入：临时文件 + `fsync` + rename。
- 跨文件事务：先写临时目录，再 rename 目录；或先写事件，再写派生文件。
- claim/release 用 `.sap.local/locks/chief.lock`：

```text
open(lock, 'wx') → 写 pid/time → 操作 → close → unlink
```

锁存在且超过 10 秒，视为 stale，允许清理。

## 4. 状态机

### 4.1 Project

```text
uninitialized
  └─ chief 点“初始化” → interviewing
interviewing
  ├─ 完成 6 题 → ready（内部）
  ├─ finalize → active
  └─ 取消 → uninitialized
active
  └─ reinit → reinitializing → interviewing → active
```

不变量：

- `active` 必须有 `direction.md` 且 `direction_version >= 1`。
- `interviewing` 不产生正式 direction；旧 direction 保留为基线/归档。
- `reinitializing` 必须已有旧 direction。

### 4.2 Chief lease

```text
none
  └─ claim → active
active
  ├─ renew（仅 lease_id 匹配）→ active
  ├─ release（主动）→ released
  ├─ agent disposed → released
  └─ TTL 到期 → expired
expired/released
  └─ claim（任意会话）→ active（epoch+1）
```

不变量：

- 一个 workspace 最多一个 `active` lease。
- 旧 lease 的 renew 必须被 epoch/lease_id 拒绝。
- claim 必须原子：锁内读-判断-写。
- `host_id` 只用于诊断，不作为在线依据。

### 4.3 角色派生

```text
isChief(session) =
  chief.session_id == session.id
  && chief.released_at == null
  && chief.lease_until > now
```

UI：

- 有效 → `总工`
- 该 session 曾是 chief 但租约失效 → `前总工（过期）`
- 否则 → session.role（none/worker）

### 4.4 Brief

```text
open → resolved
```

不变量：

- 一个 brief 一个文件；
- 只有总工/用户可 resolve；
- `resolved` 不改正文，只改 frontmatter。

## 5. 操作流程（端到端）

### 5.1 首次打开一个未初始化工作区

**触发**：用户在新工作区打开会话，SAP 条显示 `无角色` + `未初始化`。

**操作**：

1. 用户在条上点“总工”。
2. host `claimChief(sessionId)`：
   - 解析 workspace root；
   - 创建 `.sap.local` 骨架；
   - 写 `project.json`（`uninitialized`）；
   - 获取 chief 锁，写 `chief.json`（lease 30s）；
   - 写 `sessions/<sid>.json`（role none，但 chief 派生为 true）；
   - 返回 snapshot。
3. 条显示 `总工` + `未初始化`，主按钮变为 `初始化`。
4. 用户点“初始化”。
5. host `startInit()`：
   - phase → `interviewing`；
   - 生成 6 个问题；
   - 注入初始化协议到当前总工 agent；
   - 返回 `{init: {current:0,total:6,question}}`。
6. 总工 agent 在聊天里问第 1 题。
7. 用户正常回答。
8. agent 调 `sap_init_answer({answer})`：
   - service 记录答案、current+1；
   - 返回下一题；
   - 条刷新 `1/6`。
9. 重复 6 次。
10. 条出现“完成初始化”主按钮；用户点。
11. host `finalizeInit()`：
    - 写 `direction.md`（version 1）；
    - phase → `active`；
    - 写事件；
    - 返回 snapshot。
12. 条显示 `已初始化`，主按钮变为 `写 Brief`/`状态`。

**失败与回执**：

- 非总工点初始化 → `chief-role-required`；
- 已有有效总工 → `chief-already-online`；
- 无 root → `cannot-resolve-root`；
- 答案为空且无预填 → `answer-required`；
- 所有错误在面板/条上显示，不静默。

### 5.2 开一个工作会话

1. 用户新建会话。
2. 条默认 `无角色`。
3. 用户点“工作”：
   - host `setSessionRole(sid, 'worker')`；
   - 写 `sessions/<sid>.json`；
   - 注入 worker 协议；
   - 返回 snapshot。
4. 条显示 `工作`，主按钮 `写 Brief`。
5. 会话只读 `direction.md`、`briefs/`、`notes/`；写自己的 `work/`。

### 5.3 日常工作：worker 分流

**入口**：worker 收到任务。

**判断**：

- 实现细节（函数、bug、测试失败）→ 自己做，写 `work/<sid>/log.md`。
- 方向问题（目标/原则/结构/优先级/跨会话冲突/拿不准）→ 写 brief。
- 信息不足 → 问用户，不猜。

**实现**：

1. worker agent 判断为方向问题。
2. 调工具 `sap_brief_create({question, impact, options, suggestion, evidence})`，或用户在条上点“写 Brief”填短表单。
3. service：
   - 生成 `brief-<id>.md`；
   - frontmatter `status: open`；
   - 检测操作细节（stack trace/diff）→ `warning`；
   - 写事件。
4. 返回 `{id, warning}`。
5. 条显示 `已写 brief: brief-...`。
6. worker 继续做不冲突的部分，不等待。

### 5.4 总工处理 brief

1. 总工会话条显示 `未决 brief N`。
2. 点“状态”或“处理 Brief”：
   - snapshot 返回 open briefs；
   - 面板列表显示 id/title。
3. 总工选择 brief，点“写 Note”。
4. 总工 agent（或用户在面板）写结论。
5. service：
   - 生成 `note-<id>.md`；
   - 关联 brief；
   - 写事件。
6. 总工可点“标记 resolved”：
   - service `setBriefStatus(id, resolved)`；
   - 只改 frontmatter。
7. 条显示 `已写 note: note-...`、`brief ... resolved`。

**总工不做的**：

- 不读 `work/`；
- 不写 approve/reject；
- 不执行 brief 里的命令。

### 5.5 worker 读 note

1. worker 读 `notes/`（或 agent 自动检索）。
2. 采纳/调整/提异议：
   - 同意 → 按 note 调整；
   - 不同意 → 写 `work/<sid>/dissent.md`，必要时 brief v2；
   - 最多两轮，用户拍板。
3. 不把“总工没回”当通过。

### 5.6 总工离线/电脑重启

**检测**：

- host 每 10 秒续租当前有效 chief；
- `agent/disposed` → `releaseChief`；
- host 重启 → 旧 `lease_until` 到期；
- UI snapshot 每次返回 `chief.status: active|expired|released|none`。

**流程**：

1. worker 条显示 `总工离线/过期`。
2. worker 或用户点“总工”查看：
   - `chief.session_id`、`lease_until`、`epoch`。
3. 用户在新会话/原会话点“总工”：
   - `claimChief(sessionId)`：
     - 锁内检查 lease；
     - 未过期 → `chief-already-online`（显示剩余秒数）；
     - 过期/released → `epoch+1`，写新 lease；
     - 旧 session role → none；
   - 返回 snapshot。
4. 新总工条显示 `已接管`；旧总工会话若恢复，看到 `前总工（过期）`，不能续租。
5. 用户可在新总工会话点“继续”，读 direction/briefs/notes 恢复。

**关键**：

- 不是“总工进程死了”这种不可判定状态，而是“租约过期”。
- 不会出现两个有效总工。
- 不能自动把某个 worker 变成总工；必须用户点“总工”/接管。

### 5.7 重新共识（旧项目）

**触发**：旧 `.sap.local` 已初始化，但方向需要重来。

1. 总工点“重新共识”或 `/sap-init reinit`。
2. service：
   - 归档 `direction.md/init/state/chief` 到 `archive/reinit-<stamp>/`；
   - 保留 `briefs/notes/work/sessions`；
   - phase → `reinitializing`；
   - 旧答案按问题顺序预填；
   - 旧 direction 按 `##` 标题补漏；
   - 重新进入 6 题对话。
3. 条显示 `重新共识 1/6`；已回答题可“确认预填”或改。
4. finalize：
   - 写新 `direction.md`（version+1）；
   - 旧方向仍在 archive；
   - phase → active。

### 5.8 排污（方向会话被污染）

**触发**：总工发现自己读了日志/diff，或上下文被细节淹没。

1. 总工点“排污”或 `/sap-clever`。
2. service：
   - 读 `direction.md`；
   - 生成 `notes/cleanse-<id>.md`：方向摘要 + 新会话启动步骤；
   - 记录 `cleansed_at`；
   - 返回文件路径。
3. 条显示 `已生成排污包: ...`。
4. 用户新建会话 → 选“总工” → 读 direction/briefs/notes。
5. 旧会话不再承载方向判断。

**限制**：不能删除旧会话历史；真正排污是换新会话。

### 5.9 导出 / 导入 / 换机

**导出**：

1. 条“更多 → 导出”或 `/sap-export`。
2. service 打包：
   - `project.json`、`chief.json`、`direction.md`、`charter.md`、`README.md`；
   - `briefs/`、`notes/`、`templates/`；
   - `sessions/` 角色摘要；
   - **不含** `work/`。
3. 返回路径、文件数、字节数。

**导入**：

1. 条“更多 → 导入”，填 bundle 路径。
2. 默认 merge：
   - `direction.imported-*.md` 供人工确认；
   - briefs/notes 冲突加后缀；
   - 不覆盖现有 direction。
3. `--replace`：
   - 先备份到 `backups/import-*`；
   - 覆盖 direction/briefs/notes/sessions/chief；
   - 仍不碰 `work/`。

### 5.10 零散任务（无角色）

1. 会话保持 `无角色`。
2. 不注入 SAP 协议，不读写 `.sap.local`。
3. 条仍显示，但操作按钮点击提示“先选择总工/工作”。
4. 适合一次性脚本、问答、与项目无关的任务。

## 6. 服务层（唯一业务入口）

```ts
interface SapService {
  snapshot(sessionId): Promise<Snapshot>
  setRole(sessionId, role: 'none'|'worker'): Promise<Snapshot>
  claimChief(sessionId): Promise<Snapshot>
  renewChief(sessionId, leaseId): Promise<Snapshot>
  releaseChief(sessionId, leaseId): Promise<Snapshot>
  startInit(sessionId): Promise<Snapshot>
  answerInit(sessionId, answer: string): Promise<Snapshot>
  finalizeInit(sessionId): Promise<Snapshot>
  reinit(sessionId): Promise<Snapshot>
  createBrief(sessionId, input): Promise<BriefResult>
  setBriefStatus(sessionId, briefId, status): Promise<BriefResult>
  createNote(sessionId, input): Promise<NoteResult>
  appendWorklog(sessionId, text): Promise<WorklogResult>
  exportBundle(sessionId): Promise<ExportResult>
  importBundle(sessionId, path, replace): Promise<ImportResult>
  cleanse(sessionId): Promise<CleanseResult>
  doctor(sessionId): Promise<DoctorResult>
}
```

规则：

- 所有写操作先校验 session/role/lease/phase。
- 所有写操作先写事件，再写派生文件（或同一事务临时目录）。
- 所有方法返回 `{ok, ...}` 或抛 `SapError(code, message, status)`。
- UI 路由、agent 工具、命令都只调这个接口。

### 6.1 Snapshot

```json
{
  "project": {
    "phase": "active",
    "direction_version": 1
  },
  "session": {
    "id": "...",
    "role": "chief",
    "chief_valid": true
  },
  "chief": {
    "session_id": "...",
    "status": "active",
    "lease_until": "...",
    "epoch": 3
  },
  "init": {
    "current": 2,
    "total": 6,
    "question": "...",
    "can_finalize": false
  },
  "briefs": {
    "open": 2,
    "items": []
```

## 7. Agent 工具

### 7.1 初始化工具

| 工具 | 作用 | 返回 |
|---|---|---|
| `sap_init_start` | 总工开始初始化（通常由条触发） | `{phase, current, total, question}` |
| `sap_init_answer` | 记录当前问题答案，推进 | `{question, current, total, done}` |
| `sap_init_finalize` | 生成 direction，phase active | `{ok, direction_version}` |
| `sap_init_status` | 查进度 | `{phase, current, total, question}` |

初始化协议（注入总工 agent，不写入历史）：

```text
你正在主持 SAP 单机初始化。
- 一次只问一个问题；不要一次列出 6 题。
- 用户回答后，调用 sap_init_answer 记录，再问下一题。
- 6 题完成后，调用 sap_init_finalize；或提示用户点“完成初始化”。
- 不把用户回答改写成操作细节；只记录方向。
```

工具调用失败时，agent 必须把错误告诉用户，不能假装成功。

### 7.2 Brief / Note / Worklog 工具

| 工具 | 参数 | 作用 |
|---|---|---|
| `sap_brief_create` | question, impact?, options?, suggestion?, evidence? | 创建 open brief |
| `sap_brief_status` | id, status | open/resolved |
| `sap_note_create` | briefId, conclusion | 创建 note |
| `sap_worklog_append` | text | 追加 work log |

这些工具与 UI 表单共用 `SapService`，保证同一语义。

### 7.3 总工工具

| 工具 | 作用 |
|---|---|
| `sap_chief_status` | 查租约状态；worker 用它“说一嘴”总工是否在线 |

`claim` 是用户动作：只能通过操作条的“总工/接管”触发，agent 不能替用户接管。agent 可以在总工离线时提醒用户。

## 8. 操作条（控制面）

### 8.1 布局

```text
SAP v1  [无角色|总工|工作]  [状态: 未初始化 / 初始化 2/6 / 总工离线]
        [主操作]  [⋯]
```

主操作按上下文：

| 状态 | 主操作 |
|---|---|
| 无角色 | `选择角色`（展开角色） |
| 总工 + 未初始化 | `初始化` |
| interviewing | `继续初始化 2/6` |
| active + 未决 brief | `处理 Brief` |
| 总工过期 | `接管总工` |

`⋯` 菜单：

- 写 Note
- 工作日志
- 状态
- 医生
- 导出 / 导入
- 排污
- 重新共识

### 8.2 反馈状态

每个操作：

```text
idle → pending（按钮禁用，显示“处理中…”）
     → success（条上显示结果）
     → error（条上显示 error code/message）
```

不允许：

- 点击后无变化；
- 只改内存、不写文件；
- 成功但无回执；
- 错误只写 console。

### 8.3 状态刷新

- 操作响应直接返回新 snapshot；
- 页面每 10 秒拉一次 snapshot（租约倒计时/未决 brief）；
- 不做客户端乐观状态，除非回滚。

### 8.4 版本标识

条上显示 `SAP vX.Y.Z`。用于确认浏览器加载的是哪个 client bundle。

## 10. 租约算法（关键）

### 10.1 Claim

```text
lock(chief.lock)
  now = clock()
  chief = read(chief.json)
  if chief && chief.released_at == null && chief.lease_until > now:
      remaining = chief.lease_until - now
      unlock
      throw chief-already-online(remaining)
  epoch = (chief?.epoch || 0) + 1
  write(chief.json, {
     session_id, lease_id: uuid, epoch,
     lease_until: now + 30s,
     host_id, released_at: null
  })
  setSessionRole(oldChief.session_id, 'none')
  setSessionRole(session_id, 'none') // chief 由租约派生
  event('chief.claim', {epoch})
unlock
```

### 10.2 Renew

```text
lock
  chief = read
  if !chief || chief.session_id != sid || chief.lease_id != leaseId:
      throw lease-expired
  if chief.lease_until <= now:
      throw lease-expired
  chief.lease_until = now + 30s
  write
unlock
```

### 10.3 Release

```text
lock
  if chief.session_id == sid && chief.lease_id == leaseId:
      chief.released_at = now
      write
      event('chief.release')
unlock
```

### 10.4 续租定时器

- host 启动一个 10 秒 timer；
- 读当前 chief；
- 若 `ctx.agents.get(chief.session_id)` 存在 → renew；
- 否则 release（agent 已不在）；
- timer 在 plugin dispose 时清理。

不使用 `host_pid` 判断在线；`host_id` 只写诊断字段。

### 10.5 崩溃恢复

- host 崩溃：无人续租，30 秒后自然过期。
- 浏览器刷新：snapshot 显示 expired。
- 旧总工恢复：`claim` 发现 epoch 变了，旧 lease 失效；UI 显示“前总工（过期）”。
- 时钟回拨：以 host 单调时钟 + wall clock 双校验；如果 wall clock 回拨超过 60 秒，doctor 警告。

## 11. 旧状态迁移

### 11.1 检测

有 `.sap.local` 但没有 `project.json`：

- 若有 `state.json.initialized == true` → phase `active`；
- 若有 `init.json` 且 phase != done → phase `interviewing`；
- 否则 `uninitialized`；
- `legacy: true`。

### 11.2 迁移

1. 写 `project.json`（不改旧文件）。
2. 旧 `chief.json`：
   - 读 `session_id`；
   - 一律写成 `released_at = now`、`lease_until = now`（不假装在线）；
   - 写事件 `migrate.chief-expired`。
3. 旧 `sessions/*.json`：
   - `role: chief` → `role: none`（chief 由租约派生）；
   - `role: worker` 保留。
4. 生成 snapshot：
   - `legacy: true`；
   - `chief.status: expired`；
   - 主操作 `接管总工`。
5. 用户可：
   - 直接接管继续用；
   - 或 `重新共识` 归档旧 direction，保留 briefs/notes/work。

### 11.3 不回填

迁移不自动改 `direction.md`、不自动 resolve brief、不自动改 note。  
只改状态容器，内容保持原样。

| 功能点 | 操作条 | SapService | Agent 工具 / 命令 | 主要文件 | 失败回执 |
|---|---|---|---|---|---|

| 状态 | ⋯ → 状态 | `snapshot` | `/sap-status` | 派生 | `cannot-resolve-root` |
| 医生 | ⋯ → 医生 | `doctor` | `/sap-doctor` | 派生 | `not-initialized` |

| 导入 | ⋯ → 导入 | `importBundle` | `/sap-import` | `backups/*` | `import-invalid` |
| 排污 | ⋯ → 排污 | `cleanse` | `/sap-clever` | `notes/cleanse-*.md` | `chief-role-required` |

实现原则：

- 表里每个功能点只有一个 service 方法；UI、工具、命令不得各写一份。
- 每个方法先校验 phase/role/lease，再写事件，再写派生文件。
- 每个 UI 操作都必须把 service 返回的 `ok/error` 显示在条/面板。
- 命令只是 service 的薄封装，不拥有独立状态。

## 13. 测试与验收

### 12.1 单元
