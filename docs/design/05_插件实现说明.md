# dsh-sap-local 插件实现说明

> 插件源码：[仓库根目录](../../README.md)（DSH bundle 形式）。  
> GitHub 维护地址：https://github.com/DouLion/SuperAgentPlusLocal。  
> 当前状态：已在 `desktop` profile 安装并 `application: applied`；包版本 `0.1.4`。  
> 安装/升级后新开会话生效；已有会话可能需要重启 profile 才加载新的 JS 模块。  
> 本文记录实现了什么、怎么注入、怎么验证，以及哪些还没验证。

## 1. 插件做了什么

把单机版的“方向会话 / 工作会话隔离”做成 DSH 插件：

- 命令：`/sap-init`、`/sap-export`、`/sap-import`、`/sap-clever`。
- 配套：`/sap-role`、`/sap-brief`、`/sap-note`、`/sap-notes`、`/sap-status`、`/sap-qingshen`。
- 状态：`.sap.local/`，分 `direction/briefs/notes`（方向层）与 `work/`（操作层）。
- 注入：`agent/session-start` 时按 `sessions/<id>.json` 的角色，给该 agent 注册 `systemPrompt.section`；不写入聊天历史。

**没有审批**：不提供 approve/reject、G1/G2/G3、lease/grant/contract。

## 2. 命令与行为

| 命令 | 行为 |
|---|---|
| `/sap-init` | 创建 `.sap.local`；自动判断新项目/已有项目；问 6 个问题 |
| `/sap-init new` / `existing` | 指定模式重新开始 |
| `/sap-init answer <回答>` | 回答当前问题；状态写入 `init.json` |
| `/sap-init status` | 进度与当前问题 |
| `/sap-init finalize` | 生成 `direction.md`、`charter.md`、`README.md`、模板；当前会话设为 chief |
| `/sap-role none\|chief\|worker` | 设置当前会话角色；新会话默认“无角色” |
| `/sap-brief <问题>` | worker 写一页 brief；检测到 stack trace/diff 时给出警告 |
| `/sap-note <brief-id> <判断>` | chief 写方向 note（不是审批） |
| `/sap-notes` / `/sap-status` | 查看 direction/briefs/notes/角色/chief 会话 |
| `/sap-export [路径]` | 导出方向层为 JSON；不含 `work/` |
| `/sap-import <bundle> [--replace]` | 默认合并；`--replace` 先备份再覆盖 |
| `/sap-clever` | chief 排污：把 direction 摘要写进 `notes/cleanse-*.md`，提示新会话继续 |
| `/sap-qingshen` | 可选：把 SAP 总工/工作协议写入 `dsh-qingshen/modes.json` |

## 3. 注入机制：为什么不是 qingshen

本机已安装 `dsh-qingshen` 2.2.0。它的实现（`$DSH_HOME/plugins/dsh-qingshen\index.js`）：

- 监听 `agent/pre-step` 瀑布，`await next()` 后改写 `decision.messages`；
- 只改最后一条人类消息，把 `modes.json` 的 `prompt` 追加到其最后一个 text block；
- 注入文本进入会话日志；模式按会话选择，存在宿主内存。

这适合“每轮提醒”，但有两个问题：

1. 文本进入历史；如果协议很长，每轮重复，token 成本高。
2. 如果模式里带操作细节，反而污染方向会话；它不是隔离边界。

本插件选择 `agent.ctx.systemPrompt.section`：

- 按 agent 作用域注册，不写入聊天历史；
- 会话开始时根据 `sessions/<id>.json` 自动选 chief/worker，无需手动切模式；
- 插件卸载时释放 section；agent 销毁时自动清理。

可选 `/sap-qingshen` 把 SAP 协议写进 qingshen 的 `modes.json`，给“想用 qingshen 按钮”的人；**不要同时开 section 和 qingshen，否则重复注入**。

## 3.5 角色条（composer 上方）

插件带一个客户端半身，挂在 `conversation.input.dock`，显示：

`SAP  [无角色] [总工] [工作]   saved`

- 默认 **无角色**：该会话不注入协议、不参与 SAP，适合零散任务。
- 选“总工/工作”后，host 把角色写入 `.sap.local/sessions/<session-id>.json`，并按角色注入 section。
- 角色按会话记住；切回“无角色”会移除 section。
- 未初始化时显示“初始化”按钮；点击开始/继续问答，随后用 `/sap-init answer <回答>` 完成。
- 数据通路：`GET/PUT /sap-local/role`；`POST /sap-local/init` 启动初始化。

## 4. 初始化：两种模式

**新项目**（默认检测不到 `package.json`/`src`/`pyproject.toml` 等）：

1. 为谁解决什么问题
2. 当前最重要的可交付结果
3. 明确不做什么
4. 不能破坏的结构/技术约束
5. 取舍时优先保护什么
6. 什么信号该暂停/转向

**已有项目**（`/sap-init existing` 或检测到项目文件）：

1. 现在在做什么、为什么
2. 当前最重要的目标
3. 明确不做什么
4. 已有结构/模块边界/已生效决策中不能随便动的
5. 取舍原则
6. 什么情况重新看方向

`finalize` 前不开其他会话正式推进；完成后当前会话是 chief。新会话默认“无角色”，需要在输入框上方的 SAP 角色条选择“工作”或“总工”才参与 SAP；无角色会话完全不注入协议，适合零散任务。边界由 `direction.md` 固定，避免“边做边改方向”。

## 5. 导出 / 导入

导出 bundle（`sap.local/export/v1`）只含方向层：

- `direction.md`、`charter.md`、`README.md`、`state.json`
- `briefs/*.md`、`notes/*.md`、`templates/*.md`
- `sessions` 的角色摘要
- **不含** `work/`（操作细节不带去新机/新方向会话）

导入：

- 默认合并：`direction.md` 写成 `direction.imported-*.md`，briefs/notes 冲突加 `-imported-*` 后缀；不覆盖现有方向。
- `--replace`：先把 direction/briefs/notes/sessions 备份到 `backups/import-*`，再覆盖；仍不碰 `work/`。
- 导入后需要人工确认 `direction.imported-*.md` 是否替换 `direction.md`。

## 6. 排污（/sap-clever）

命令不能删除当前会话历史（DSH 没有这个 API）。它做的是：

1. 读 `direction.md`；
2. 生成 `notes/cleanse-<id>.md`：方向摘要 + 新会话启动步骤；
3. 在 `sessions/<id>.json` 记 `cleansed_at`；
4. 提示：新建会话 → `/sap-role chief` → 只读 direction/briefs/notes。

真正“排污”是**换一个干净会话**，不是让旧会话忘记。命令提供的是可带走的干净方向包。

## 7. 安装与验证

安装：

- 插件目录：`仓库根目录`
- 已通过 `plugin_manager install_bundle` 安装到 `desktop` profile；`application: applied`。
- profile 的 `package.json` 有 `dsh-sap-local` 链接；`node_modules/dsh-sap-local` 指向工作区目录。

测试：

- `node --test dsh-sap-local/test/*.test.js`：10 个测试通过。
- 覆盖：findRoot、init 全流程、brief/note、export/import merge/replace、cleanse、命令注册、角色注入、qingshen 模式写入、角色条 host 路由（none/chief/worker）、初始化按钮路由。

**未验证**：

- 没有在 GUI 新会话里实际点 `/sap-init` 看按钮/输出；命令 handler 已用 mock agent/ctx 测试，安装结果 `applied`。
- 没有验证 `systemPrompt.section` 在当前 DSH 会话中的实际渲染；代码按 `dsh-system-prompt` 的公开 API 编写，但未做端到端会话检查。
- 修改插件代码后，已重新安装；DSH 可能需要重启 profile 才加载新的 JS 模块（替换已安装包通常需要 restart）。
- qingshen 的 `<modes.json>` 写入只在本机路径上测试；不同 profile/安装位置需重新确认。
