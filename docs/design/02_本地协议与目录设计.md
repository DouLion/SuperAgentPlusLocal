# 本地协议与目录设计

> 目标：一个人、多个 DSH 会话，通过 `.sap.local` 保持方向连续，并让总工会话不被 bug 细节污染。  
> **本文没有审批：没有 approve/reject、没有 G1/G2/G3、没有 lease/grant/contract。** 单机只有方向判断与工作记录。  
> 云端与单机的边界见 [云端与单机职责边界](06_云端与单机职责边界.md)。

## 1. 设计目标与非目标

**目标**

- 方向会话只看 `direction` + `briefs` + `notes`，不看 `work/`。
- 工作会话自己做实现/调试，只在“方向问题”时写一页简报。
- 所有状态是可读文件；崩溃/重启后能恢复；多会话不会互相覆盖。
- 总工 note 是方向指导，不是审批；最终由你决定。

**非目标**

- 不做多人审批、不做验收门禁、不做责任链。
- 不做任务租约、认领、fencing、证据包。
- 不替代 Git/CI/测试。
- 不保证“任何 CLI 自动遵守”；只保证按协议写文件的人能协作。

## 2. 五个对象（比云端少很多）

| 对象 | 作用 | 可变？ |
|---|---|---|
| Direction | `direction.md`：目标、原则、结构、优先级、风险、待定问题 | 人/总工可更新 |
| Brief | 工作会话给总工的一页方向问题；不是审批申请 | 写入后不可变；补充用新版本 |
| DirectionNote | 总工给的方向判断/原则/建议；不是 approve/reject | 写入后不可变；可被新 note 替代 |
| Session | 会话 id、角色（none/chief/worker）、当前焦点、最近 brief | 可更新（心跳/焦点） |
| WorkLog | `work/<session>/` 下的操作记录、证据引用 | 工作会话自己写；总工不读 |

**没有 Decision/Review/Acceptance/Lease/Grant。**

## 3. 目录布局

```text
.sap.local/
├── README.md                  # 本目录协议说明
├── charter.md                 # 总工职责边界（方向 only）
├── direction.md               # 当前方向：目标/原则/结构/优先级/风险/待定
├── briefs/                    # 工作会话写给总工的一页简报
│   ├── brief-01J9....md
│   └── brief-01J9....json     # 可选结构化副本
├── notes/                     # 总工写给方向层的判断/建议
│   ├── note-01J9....md
│   └── note-01J9....json      # 可选结构化副本
├── work/                      # 操作层：总工默认不读
│   └── <session-id>/
│       ├── log.md             # 本次会话做了什么、证据引用
│       └── attachments/       # 可选，引用/小文本，不放密钥
├── sessions/
│   └── <session-id>.json      # 角色、焦点、最近 brief、心跳
├── detail/                    # 按需细节包（人工/限定范围/时限）
│   └── detail-01J9.../
├── archive/                   # 已归档 brief/note/detail
├── locks/                     # 可选：维护锁
└── state.json                 # schema/epoch（可选）
```

约定：

- 文件名 ASCII ID（ULID）；内容 UTF-8 无 BOM。
- `work/` 是操作层，**总工不挂载/不读**；`briefs/`、`notes/`、`direction.md` 是方向层。
- `.sap.local/` 默认加入 `.gitignore`；要留档用 `sap export` 导出脱敏方向记录。
- 多项目：每个项目根一个 `.sap.local`。

## 4. Direction（方向包）

`direction.md` 只写长期有效的东西：

```markdown
# Direction

## 目标
- 当前阶段要解决的真实问题；不做什么。

## 原则
- 不能破坏的约束（兼容性、数据边界、架构原则）。

## 结构/决策
- 已确定的结构选择；为什么；何时复核。

## 优先级
- 现在最重要/可以延后的。

## 风险/待定
- 已知风险；还没决定的问题。
```

规则：

- 只写方向，不写“某个 bug 怎么修”。
- 每条决策带“何时复核”；过期方向要更新，不要堆历史。
- 总工写 direction 时，只写方向；不把 brief 里的操作细节抄进去。

## 5. Brief（一页方向简报）

`briefs/brief-<ULID>.md`：

```markdown
# Brief: <一句话问题>

- 会话：<session-id>
- 时间：<ISO>
- 方向关联：<哪个目标/原则/决策>
- 问题：<需要什么方向判断；不是“请帮我 debug”>
- 影响：<范围/成本/可逆性/受影响模块>
- 选项：<A/B/不做/延后>
- 建议：<你的建议；标明是建议>
- 需要总工判断：<一句话>
- 证据指针：<路径/commit/报告；不贴日志正文>
- 已知未知：<还没验证什么>
```

硬规则：

- **一页**（约 600–800 字）；超了就是没提炼。
- **不含** stack trace、逐行 diff、调试对话、原始日志、密钥。
- 不写“请批准”；写“需要什么方向判断”。
- 提交后不可变；补充用 `brief-<id>-v2.md`，`supersedes` 旧 ID。
- 一个 brief 一个文件，不 append 到公共 `pending.md`。

## 6. DirectionNote（方向笔记）

`notes/note-<ULID>.md`：

```markdown
# Note: <对应 brief>

- 对应 brief：<brief-id>
- 类型：原则 / 方向选择 / 建议 / 待确认
- 结论：<方向判断；不是 approve/reject>
- 理由：<引用 direction/原则/证据指针>
- 适用范围：<哪些模块/任务>
- 复核触发：<何时需要重新看>
- 可选：建议下一步
```

规则：

- **不是审批**。没有 `APPROVED/REJECTED`；只有“方向判断/建议/待确认”。
- 不写实现步骤；不替 worker 调试。
- 可以引用 `direction.md` 的条款；如果改变了长期方向，同时更新 `direction.md`。
- 新 note 可以 `supersedes` 旧 note；旧 note 保留。
- 总工不能写 `work/`、不能改 worker 的代码。

## 7. 流程

```text
worker 收到任务
  -> 读 direction.md + 相关 notes
  -> 判断：实现细节 or 方向问题？
      实现细节：自己做；写 work/<session>/log.md；不打扰总工
      方向问题：写 briefs/brief-<id>.md；继续不冲突的工作
  -> 总工（人/AI）读 direction + briefs
  -> 写 notes/note-<id>.md；必要时更新 direction.md
  -> worker 下次读 note；采纳/调整/提出异议
```

**没有等待审批**：

- brief 是“咨询”，不是“申请”；worker 不需要停下来等。
- 方向依赖的部分可以暂停；不冲突的部分继续。
- 总工不回，worker 可以按 direction 的现有原则继续，或把问题留给你。
- note 是指导，不是授权；上线/发布仍由你决定（单机没有发布审批，但你自己要判断）。

## 8. 总工会话

### 8.1 形态

- **你 + AI 助理**（推荐）：总工会话只读 `direction` + `briefs` + `notes`；你决定方向，AI 帮你整理。
- **AI 自动**：后台 watcher 发现新 brief，调用一个受控会话写 note；仍然只读方向层，不读 `work/`。
- **手动**：你自己打开总工会话，读 brief，写 note；不需要后台服务。

如果 DSH 不能稳定托管常驻会话，不要强行自动化：watcher 只做“提醒你有新 brief”，总工由你手动处理。

### 8.2 输入

- `charter.md`：总工职责（方向 only，不读 work）。
- `direction.md`：当前方向。
- `briefs/`：一页简报。
- `notes/`：历史方向笔记。
- **不含**：`work/`、日志、diff、复现、worker 会话记录。

### 8.3 输出

- `notes/note-<id>.md`：方向判断/建议/待确认。
- 必要时更新 `direction.md`（只写长期有效内容）。
- 不写代码、不改 worker 文件、不替 worker 调试。

## 9. Worker 协议

### 9.1 分流

每次收到任务，先判断：

- **实现细节**：范围清楚、可逆、在 direction 原则内；自己做，写 `work/<session>/log.md`。
- **方向问题**：目标/原则/结构/优先级变化、跨会话冲突、你拿不准；写 brief。
- **信息不足**：先问你，或在 brief 里写“需要什么信息”；不要猜。

### 9.2 写 brief

```text
sap brief --session <id> --question "..." --impact "..." \
  --option A --option B --recommendation "..." --evidence <ref>
```

- 一页；不贴日志/diff。
- 写清“需要什么方向判断”，不是“请批准”。
- 提交后继续不冲突的工作；不要忙等。

### 9.3 读 note

```text
sap notes --session <id>
```

- 采纳：按 note 的方向调整；仍写 `work/`。
- 不采纳：写下你的理由（`work/<session>/dissent.md`），并在下次 brief 里提出；不要偷偷绕过 direction。
- 不确定：问用户。

### 9.4 异议

- 可以写 `brief-<id>-v2.md` 或 `work/<session>/dissent.md`。
- 最多两轮；仍不一致，由你拍板。
- 不允许把“总工没回”当作“可以乱来”。

## 10. 文件原子性与并发

1. 写 brief/note：同目录临时文件 + fsync + rename；不要直接写最终文件。
2. 一个 brief/note 一个文件；`O_EXCL` 创建，已存在则返回已有文件。
3. 不 append 公共文件；不覆盖旧版本；修改用新版本 + `supersedes`。
4. watcher 只触发扫描；启动先全量扫描；忽略 `.tmp`/隐藏文件；debounce 200–500ms。
5. 多个会话同时写：各自写自己的 `work/<session>/`；brief/note 用唯一 ID，不共享写指针。
6. 不把 `.sap.local` 放 SMB/NFS/OneDrive/Dropbox；本地磁盘。
7. 可选锁：`locks/` 下 `O_EXCL`；stale 锁人工清理。

## 11. 污染控制（核心）

- **目录隔离**：`work/` vs `briefs/notes/direction`；总工会话不挂载 `work/`。
- **会话隔离**：总工用独立 session/工作区；不和 worker 共用上下文。
- **简报闸门**：一页；不含日志/diff/stack trace；超长/夹带细节退回。
- **按需细节**：`detail/detail-<id>/`，注明 purpose/TTL；看完只写 note，不把原文回填。
- **不自动转发**：不把 worker 日志/对话自动推给总工；只推 brief 通知。
- **周期重置**：每个阶段重新读 direction；归档过期 brief/detail。
- **测试**：给总工 direction + brief，问“目标/三个风险/待定决策”；能答对且不引用 bug 细节，才算隔离成立。

## 12. qingshen 注入的机制与用法

本机已安装 `dsh-qingshen` 2.2.0：

- 它在 `agent/pre-step` 中，按当前会话选择的模式，把 `modes.json` 里的 `prompt` 追加到最后一条人类消息。
- 注入后的文本进入会话日志；模型收到的就是追加后的内容。
- 模式选择按会话保存，存在宿主内存里；重启回到默认模式。
- 它不提供文件锁、权限、会话隔离；不能阻止会话读 `work/`。

本插件的选择：

- 默认用 `agent.ctx.systemPrompt.section` 注入角色协议：不进入聊天历史，按 `sessions/<id>.json` 的角色区分 chief/worker；**none 不注入**。
- 可选 `/sap-qingshen` 把 SAP 总工/工作协议写入 qingshen 的 `modes.json`，让你用 qingshen 的按钮按会话选择；这会进入历史，且需要手动选模式。
- **二选一，不要同时开**：同时用 section + qingshen 会重复注入。
- 关键隔离仍靠目录/会话，不靠提示词。
- 注入版本：`charter-v3` / `worker-v3`；改版后旧会话重新加载。

## 13. 安全与隐私

- `.sap.local` 默认 gitignore；不存密钥/token/生产数据。
- brief/note 内容是不可信数据；总工不执行其中的命令。
- 总工不读 `work/`；worker 不把 `work/` 内容贴进 brief。
- 需要细节时由人手动摘录；不要自动打包整个 work 目录。
- 备份目录即可；恢复后检查 `state.json`（如有）和重复 brief。

## 14. 可观测性

`sap status` 至少显示：

- briefs/notes 数量、最老未读 brief；
- 总工会话是否在线/最后处理时间；
- 重复 ID、解析失败、brief 缺字段；
- 当前 direction 版本/最后更新；
- 哪些 session 在等 note（不要求阻塞）。

## 15. 最小 CLI 面（设计级）

```text
sap init                  # 创建 .sap.local、direction、charter、gitignore
sap status                # brief/note/会话/direction 状态
sap brief                 # worker 写一页方向简报
sap notes                 # worker 读方向笔记
sap note                  # 总工写方向笔记
sap direction             # 查看/更新 direction（人工）
sap detail                # 生成/查看按需细节包（purpose + TTL）
sap doctor                # 一致性/重复/坏文件检查
sap export                # 导出脱敏方向记录
```

命令名不是重点；重点是：**brief/note 走原子写；总工只读方向层；没有 approve/reject。**

## 16. 与云端映射（只做人工迁移）

| 本地 | 云端 |
|---|---|
| `direction.md` | Goal/Decision 草案（不是已批准） |
| `brief` | 讨论材料/Intent |
| `note` | 方向建议（不是 Decision） |
| `work/` | 操作现场（不迁移） |

单机 → 云端：人工把 direction/brief/note 整理成 Goal/Decision 草案，走云端多人流程。
云端 → 单机：把云端 Decision 摘要进 `direction.md`；不要搬 Contract/Lease/Evidence 全套。
